# REEL Originals P001 · Actual Shot Media Evidence and Human Editorial Intake

**Status:** local user-selected MP4 verification tooling. **No real model-produced REEL shot is known to exist yet.** A green CI check here does not imply the pilot has been rendered, reviewed or published.

## First shot: the grounded path from CineSwarm to ParaCut

The v3.6 Wan2.1 first-shot preflight was the preparation step. This release enables inspecting evidence **only after an operator has actually submitted and finished a native REEL P001-S01 job** in CineSwarm.

After CineSwarm companion [PR #6](https://github.com/MichaelWave369/CineSwarm/pull/6) merges:

1. A human runs the qualified native CineSwarm video job on their own installed model/hardware, within proper license and producer authorization. REEL's public GitHub Pages site cannot execute this step.
2. CineSwarm stores **real** Wan 2.1 native (832×480, 16 fps) and scaled master (1280×720, 24 fps) MP4 files, SHA-256 checksums, ffprobe reports and hash-chained job/shot/asset/QC receipts. A separate human may `ACCEPT`, `REJECT` or request revision against the actual master hash. These reviews are about media QC, **not** publishing authorization.
3. With the *actual* master artifact UUID and correct coordinator data root, a user runs:

   ```bash
   python -m cineswarm.reel_media_evidence --data-root ./parallax-cineswarm-data --artifact-id <REAL-MASTER-UUID> --out reel-p001-shot-one-evidence.json
   ```

   The offline command opens existing CineSwarm SQLite using read-only mode, replays the entire receipt chain, checks job/shot/source lineage and live native/master bytes plus fresh `ffprobe`, then exports an **unsigned** `REEL_P001_REAL_MEDIA_EVIDENCE_V1` JSON sidecar. No background server, generation, uploads or rights authorization are involved. It does not copy the MP4 into the sidecar.
4. In ReelCommons **REEL Network → Pilot 001 → Evidence & Preview Desk**, explicitly choose that JSON and the **actual master MP4** using two separate local file pickers. The React app checks exact schema, denies all rights/publishing claims, verifies the source hash against the active exported pilot kit if present, confirms a basic MP4 file signature, and **recomputes SHA-256 over every selected MP4 byte** in WebCrypto. Its selected master file must match the sidecar's exact hash and length.
5. Only a matching file enables the manual HTML video player. Playback is local, never automatic. The browser displays the native back-end **as a claim in unsigned local evidence**, the existing QC review status, and an explicit reminder that *QC ACCEPT is not release approval*. If the browser cannot decode the MP4 codec, integrity validation can still succeed, but the user must inspect media in a compatible player/editor.
6. The creator can then **manually import that same local MP4 into ParaCut** using ParaCut's established file workflow, while retaining the CineSwarm evidence sidecar for postproduction reference. This does **not** auto-generate a native ParaCut project or WaveForgeStudio release receipt.

## What counts as evidence (and what doesn't)

A JSON file and an MP4 with matching SHA-256 establish **file-byte consistency with the declared digest**. They do not prove the file was generated by Wan2.1, an authorized GPU operator, a consented narrator, a legitimate music owner, or a rights-cleared project. Local CineSwarm reads and hashes its own actual SQLite records/MP4s, but the export is **not signed** and the public browser cannot independently authenticate the database's origin or the device.

Without the active source kit in memory, the browser flags the evidence **UNLINKED_UNSIGNED_SOURCE**, never “verified origin.” If the local evidence reports ACCEPT, REJECT, REVISION_REQUESTED or PENDING_REVIEW, the UI preserves the exact status and denies public-release rights in every case.

For performance and safety, the browser verifies at most **256 MiB** of a selected MP4 in one memory-backed WebCrypto digest. Larger genuine files require a future streaming-hash/desktop adapter; they are not silently trusted.

The 50 official RCTV channels remain unchanged. This release does **not** append CH 051, auto-promote any playable URL, submit jobs, collect livestream input, proxy an external media source, publish a podcast, or connect to CineSwarm's local coordinator.
