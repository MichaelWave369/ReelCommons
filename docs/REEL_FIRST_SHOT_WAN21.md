# REEL Originals P001 · Shot 001 Real-Backend Production Readiness

**Status:** production preparation, **not** executed or published media.

The live REEL storyboard now has a **First-Frame Production Preflight** section below Pilot 001's script/download desk. It targets the first eight-second scene **“The Unlit Screen.”** This is the first bridge that can prepare a **real Wan 2.1 T2V 1.3B production-plan candidate** rather than the prior deterministic simulation.

## Full workflow

1. In REEL Network, review Pilot 001 and click **Download preproduction JSON**.
2. After CineSwarm companion PR #5 is merged, open a local CineSwarm Python environment and run:
   
   ```bash
   python -m cineswarm.reel_shot_one reel-p001-preproduction.json --out p001-shot-one-preflight.json
   ```
   
   This converts the exact eight-scene, all-unreviewed storyboard into a one-shot **native Wan2.1 candidate** with proper SHA lineage, without contacting a coordinator or executing a model. The output contains only a single first shot and all claims of rendered media, verified rights and authorization are false.
3. To check that your workstation actually has compatible available hardware **and correctly pinned source/model bytes**, run a separate command with `--check-local` and a new `--out` filename. This is optional and inspects local hardware and checkpoint files only. The local tool never downloads or renders models.
4. Return to **REEL → Pilot 001 → First-Frame Production Preflight** and explicitly select the JSON result. The browser validates the exact single-shot WAN21 plan, original scene time, no-conditioning, denied release flags and SHA-256. If the same preproduction packet remains loaded in the current browser, it verifies that the native shot prompt and lineage match the exported kit. Otherwise it labels the result an **unlinked editable file**.
5. Examine the status: `NOT_CHECKED`, a specific `BLOCKED_*` reason, or `OPERATOR_REVIEW_REQUIRED`. The latter is **not** production approval; it only reports local declared model bytes and scheduler resource checks.

## Real GPU constraints

Native CineSwarm Wan 2.1 T2V 1.3B requires **9216 MiB free VRAM on a single GPU** (not combined across cards), **16384 MiB free RAM** and **20480 MiB free disk**. The backend also needs operator-pinned official Wan 2.1 source and a local T2V 1.3B checkpoint whose SHA-256 directory hash matches the operator-supplied expected value. The model's license and the intended commercial/publishing usage need a real operator review, not a checkmark generated by code.

The native MP4 target is **832×480 at 16 fps**; the later 1280×720 delivery master is explicitly **scaled and converted to 24fps**, not native 720p. The existing CineSwarm Wan21 backend implements this production route already. The new receiver only prepares the candidate and reports readiness.

## Separate execution / publication gates

No browser feature here can submit to CineSwarm, run a video job, access the operator's machine, mint a copyright license, approve a generative model checkpoint, or register a public RCTV channel. A human must independently authorize an actual plan submission, local runtime, model checkpoint/license, creative brief, original IP rights and cost. After a **genuine** render the operator can inspect and accept/reject the **exact artifact hash**. Human-owned voice narration, original music, ParaCut assembly, WaveForge reference receipt and public REEL release remain later stages.

Existing RCTV **CH 001–050** and reviewed NASA/KEXP routes remain fixed. Pilot P001 remains a **PREPRODUCTION DRAFT**, not an episode on air.

## Quality assurance

The new React `src/reelFirstShot.test.tsx` test suite checks no-autoplay UI, exact source/plan hashes, first-shot Wan21 native constraints, forged release and provider substitution rejection, unlinked source labeling, reported readiness states and unchanged RCTV catalog. Native CineSwarm companion `tests/test_reel_shot_one.py` checks backend candidate schema, all eight storyboard scenes, human review flags, CLI non-overwrite, model hash mismatch, and profile selection for 12GB versus underqualified GPUs.

Physical GPU inference and browser file-download handoffs are **not** validated by GitHub CI. This milestone is intended to make the next human-controlled production run technically specific and reviewable, not to claim one happened.
